# 공통 배치 — 회사 적용 지침

KRDS 2024 PDF p88–100은 정보 구조·배치 검토의 참고 자료다. 실행 외형은 v27 회사 팩만 사용하며 원문의 정부 식별자·과거 그리드 CSS는 포함하지 않는다.

<a id="usage"></a>
## usage

- G01: 주요 과업과 정보 구조에 따라 제한 폭/유연 폭 및 사이드 메뉴 유무를 선택한다. 복잡한 하위 정보가 없으면 사이드 메뉴를 억지로 추가하지 않는다. 회사 공통 헤더·푸터는 유지하고 본문의 업무 정보는 목적에 맞게 구성한다.
- G02: v27의 페이지 기본 여백20px과 선택한 회사 컴포넌트의 간격을 적용한다. 열 수는 업무 정보에 맞게 정하며 원문의 4/8/12열을 모든 화면에 강제하지 않는다. 칼럼은 유연한 비율이며 화면 여백과 거터를 구분한다.
- G03: 제한 폭과 유연 폭을 업무에 맞게 구분한다. 선택한 회사 레이아웃의 실제 breakpoint 전후에서 재배치를 확인하고 360px보다 좁거나 글자가 확대된 경우에도 잘라내지 않는다. 사이드 메뉴의 좁은 화면 대안은 본문 앞 순서를 유지한다.
- G04: 페이지 제목→본문, 구역→구역, 제목→설명, 문단→문단의 간격을 v27 공통 CSS 역할로 적용한다. 관련 없는 영역과 같은 영역 안의 항목 간격을 혼동하지 않는다. 원문 p99/100의 32px 예시를 회사 컴포넌트 값 위에 덮어쓰지 않는다.
- G05: 예제의 내용·메뉴를 실제 과업으로 교체하고 제목 계층, DOM 읽기 순서, 링크 목적지와 초점, 빈/긴 콘텐츠를 확인한다. 전체 페이지를 여러 번 복제하지 말고 선택한 article 골격과 의존 CSS만 사용한다.

## 참고 및 적용 경계

- p90/91 모바일 대안 6열과 p94의 8열은 원문 불일치이며 회사 열 수의 권위가 아니다. 회사 구성은 v27 배치와 업무 계약에서 확정한다.
- p95의 1280px 정부 기관 제한은 회사의 법적 의무나 실행 기본값이 아니다.
- CSS 토큰이 존재한다는 사실은 개별 앱의 반응형·접근성 검증을 대체하지 않는다.
