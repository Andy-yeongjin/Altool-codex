## 미완료 검증

이 항목은 최초 구현 시점 기록이다. 담당 PDF 시각 열람 상태와 추가 검증의 현재 결과는 맨 아래 최종 원문 대조 기록 및 `pdf-visual-review.json`을 따른다.

- **실제 브라우저 조작/반응형/콘솔/네트워크:** 부모 에이전트 검증 대기. 담당 에이전트는 브라우저를 조작하지 않았다.
- **원 PDF 그림·레이아웃·강조된 적용 수준 전수 대조:** 미완료. 추출 텍스트의 `필수 권장 우수`를 임의 선택하지 않았다.
- **스크린 리더·모바일 실기기·백그라운드 세션 타이머:** 미검증.
- **실제 인증·권한·신청·심사·행정정보 연계:** 샘플 범위에 포함하지 않음. 현업 서비스 완성으로 보고할 수 없다.
- **모든 조건부 유형·변형:** 아래 확장 구현 후 contracts.json의 uiVariants/gaps로 분리했다. 원문 연결·체크리스트는 실행 코드의 전수 검증 증거가 아니다.

브라우저 시나리오는 [README.md](README.md)의 검증 목록을 따른다. 상위 통합 검증에서 실제 관찰 결과를 기록한 후에만 해당 범위의 상태를 승격한다.

## 2026-09-08 · 부모 브라우저 발견: 임시 저장 시각 표시

부모가 실제 브라우저에서 `생활 안전 / 방문 / 오후` 선택 후 임시 저장했을 때, 저장 자체와 새로고침 복원은 정상이지만 폼 하단은 여전히 “아직 임시 저장하지 않았습니다”로 남는 문제를 확인했다.

- 저장 성공 시 하단 `draft-saved-at`의 문구를 마지막 저장 시각으로 즉시 갱신했다. 화면 구조는 변경하지 않았다.
- 저장 실패 시 마지막 성공 시각/안내를 유지한다.
- 실제 `save-draft` 핸들러를 가짜 DOM 노드와 성공·실패 저장소로 실행하는 회귀 테스트를 추가했다. 수정 전 해당 테스트1건 실패를 확인했고, 수정 후 **17개 전체 통과**했다.
- 실제 브라우저 수정 후 재검증은 부모에게 요청했다. 이 단위 테스트만으로 브라우저 재검증 완료를 주장하지 않는다.

## 2026-09-08 · 부모 브라우저 발견: 신청 선택지 시작 태그

부모의 실제 선택 조작에서 `디지털 기초`, `온라인`, `오전` 선택지가 일반 텍스트로 렌더되고 선택되지 않는 문제를 확인했다. 세 선택지의 `<option>` 시작 태그가 누락된 것이 원인이었다.

- 누락된 시작 태그3곳만 추가했다. 담당 폴더에서 동일한 닫기 태그 뒤 고아 텍스트 패턴은 더 발견되지 않았다.
- 실제 양식의 `main.innerHTML` 할당문을 VM으로 평가한 마크업에서 세 select의 옵션 배열과 고아 텍스트 부재를 검사했다.
- 담당 HTML/JS의 모든 select 템플릿에 option 시작/종료 태그 수 대조를 추가했다. 일반 컨테이너·폼·레이블·목록·제목·설명목록 태그의 짝도 정적으로 대조해 불일치를 발견하지 않았다.
