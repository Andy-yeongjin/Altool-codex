# 개인 식별 정보 입력

출처: 행정안전부, 디지털 정부서비스 UI/UX 가이드라인(2024.02), PDF p.553–572. 공공누리 제1유형. [원문 참고](../../reference/krds-p0553.md).

## 재사용 범위

[실행 예제](identity.html)는 Altool이 독립 제작한 프런트엔드 조합 예제다. 공식 구현이나 접근성 인증이 아니며 실제 수집·제출·외부 API 호출은 하지 않는다. `basic.css`, `basic-core.js`, `basic.js`를 함께 사용하고 필요한 패턴의 초기화와 DOM만 선택한다. 고객 디자인 원본이 있으면 해당 시각 계약을 우선한다.

### 제공한 상태·변형

- 이름·생년월일·성별·전화 입력 구조
- 잘못된 날짜/전화 오류, 무응답 성별, 보존된 입력
- 국가 코드 콤보박스·추가번호·주연락처

## 원문 적용 체크리스트

다음은 적용 프로젝트에서 확인할 목록이다. 항목 존재/자동 테스트를 전체 의미적 준수로 해석하지 않는다. 부적합 예제·실제 기관 브랜드·개인정보는 기본 자산으로 복제하지 않았다.

- [ ] BP-553-01: 개인 정보가 꼭 필요한지 먼저 확인하고, 각 항목의 수집·활용 목적을 인접 설명으로 알린다.
- [ ] BP-553-02: 복사·붙여넣기를 막지 않고 실제 값·성별·국가 코드의 기본값을 강제하지 않는다.
- [ ] BP-553-03: 이름은 단일 필드로 받고 모든 언어·공백·기호·숫자를 허용한다. 짧은 이름이나 긴 이름에 임의의 3~5자 제약을 두지 않는다.
- [ ] BP-553-04: 개명한 사용자의 이름을 막지 않으며 실제 인증기관에서 제약이 생기면 변경 절차 도움말을 제공한다.
- [ ] BP-553-05: 생년월일은 달력이나 연도·일 셀렉트 대신 형식을 설명한 텍스트 입력을 쓴다.
- [ ] BP-553-06: 성별은 기본 선택을 없애고 선택 안 함을 제공한다.
- [ ] BP-553-07: 목적상 필요하지 않다면 휴대전화만 강요하지 않는다. 전화 유형·각 번호의 레이블을 명확히 한다.
- [ ] BP-553-08: 공백·하이픈·대시·괄호 전화 형식을 허용한다. 국가명+코드 콤보박스를 제공한다.
- [ ] BP-553-09: 여러 번호를 받으면 각각 구분하고 주 연락처 선택을 제공한다.
- [ ] BP-553-10: 개인 식별 입력은 name, bday, tel 등 목적에 맞는 autocomplete를 제공한다.

## 실제 브라우저 재검증 시나리오

1. 이름에 'Li'나 한 글자 입력 → 허용, 20240230 → 날짜 오류/값 보존
2. 생년월일 수정·선택 안 함·공백 전화 입력 → 형식 확인 성공
3. 추가번호 없는 사무실 주연락처 선택 → 오류, 기본 radio 선택 없음 확인
4. 390px/1280px에서 잘림·겹침·포커스·주요 동작·콘솔 오류를 확인한다. 키보드와 실제 스크린리더 확인은 별도이며 정적 마크업 검사로 대체하지 않는다.

## 미적용·잔여 검증

- 실제 개인 식별·인증·개명 동기화·국가별 번호 정합성은 미구현이며 서비스 계약이 필요하다.
- 브라우저의 datalist 자동완성 동작·스크린리더 조합은 수동 검증이 필요하다.
- 모든 항목이 한 화면에 있는 것은 유형 전시 목적이다. 실제 서비스에는 필요한 필드만 선별한다.
- 이 파일 작성 시 실제 브라우저 조작 검증은 부모 작업에 인계했다. 자동 규칙/마크업 검사 결과는 `README.md`의 검증 명령과 별도 작업 보고를 확인한다.
