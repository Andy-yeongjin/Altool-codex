# 필터링·정렬

출처: 행정안전부, 디지털 정부서비스 UI/UX 가이드라인(2024.02), PDF p.656–676. 공공누리 제1유형. [원문 참고](../../reference/krds-p0656.md).

## 재사용 범위

[실행 예제](filter.html)는 Altool이 독립 제작한 프런트엔드 조합 예제다. 공식 구현이나 접근성 인증이 아니며 실제 수집·제출·외부 API 호출은 하지 않는다. `basic.css`, `basic-core.js`, `basic.js`를 함께 사용하고 필요한 패턴의 초기화와 DOM만 선택한다. 고객 디자인 원본이 있으면 해당 시각 계약을 우선한다.

### 제공한 상태·변형

- 6유형 필터·일괄/즉각·관계형 하위옵션
- 사이드패널·축약/펼침·제목인라인정렬·범위오류
- 적용칩/개별·전체초기화/결과live·페이지/빈결과
- [수평바·모달 배치 대안](filter-layouts.html): 같은 입력폼을 배치에 맞게 이동하고 모달 취소 시 적용 전 조건 복원

## 원문 적용 체크리스트

다음은 적용 프로젝트에서 확인할 목록이다. 항목 존재/자동 테스트를 전체 의미적 준수로 해석하지 않는다. 부적합 예제·실제 기관 브랜드·개인정보는 기본 자산으로 복제하지 않았다.

- [ ] BP-656-01: 데이터에 맞게 텍스트·스코프·선택·범위·쿼리·관계형 필터를 선택한다. 필요 이상의 옵션을 강제하지 않는다.
- [ ] BP-656-02: 즉각 표시와 일괄 표시를 처리 속도·조건 수에 맞게 선택한다.
- [ ] BP-656-03: 수평막대·인라인·사이드패널·모달은 화면공간/과업에 맞게 선택한다.
- [ ] BP-656-04: 충분한 공간에서는 주요 필터를 숨기지 않고 선택값을 분명히 표현한다.
- [ ] BP-656-05: 적용 조건·조건 수·결과 수와 개별해제·전체해제를 제공한다.
- [ ] BP-656-06: 필터·정렬에 간결한 레이블과 그룹헤딩을 제공하고 핵심옵션부터 배치한다.
- [ ] BP-656-07: 관련 속성은 묶고 관계형 선택의 하위 옵션을 상위 속성과 맞춘다.
- [ ] BP-656-08: 정렬은 목록 우상단, 인라인 정렬은 열 헤더에 배치한다.
- [ ] BP-656-09: 실제 메타데이터가 색인화·검색 가능하며 옵션별 결과를 반환하는지 검증한다.
- [ ] BP-656-10: 날짜/시간은 범위를 입력할 수 있게 하고 3개 이상 속성에는 전체 초기화를 제공한다.
- [ ] BP-656-11: 좁은 화면에 축약 컨트롤을 쓴다면 필터→정렬 순서와 접근성을 보존한다.
- [ ] BP-656-12: 변경된 결과 수는 assertive live region으로 알린다.
- [ ] BP-656-13: 즉각 갱신 후 선택 컨트롤, 일괄 적용 후 제출 버튼의 초점을 유지한다.
- [ ] BP-656-14: 인라인 정렬은 키보드/클릭으로 오름·내림을 바꾸며 프로그램적 정렬 상태를 전달한다.

## 실제 브라우저 재검증 시나리오

1. 분야선택 일괄모드→목록 미변경→적용→변경/초점 유지
2. 즉각모드·지역 남부→나래구만 옵션·날짜 역순 오류
3. 조건칩해제/초기화/없는단어0개/제목정렬토글/필터접기·펼치기/페이지
4. 대안 페이지 수평바에서 교육 적용 →12개, 초기화→24개. 모달 배치로 바꿔 필터 열기 → 생활 선택 후 취소/Escape →24개 유지. 다시 열어 생활 적용 →12개+모달 닫기+열기 버튼 포커스.
5. 대안 페이지 날짜 역순→오류+종료일 포커스, 수정→적용, 개별해제/초기화/없는 검색어/정렬/페이지를 확인한다.
6. 390px/1280px에서 잘림·겹침·포커스·주요 동작·콘솔 오류를 확인한다. 키보드와 실제 스크린리더 확인은 별도이며 정적 마크업 검사로 대체하지 않는다.

## 미적용·잔여 검증

- 수평바·모달 변형은 별도 대안 페이지로 제공한다. 모달 적용 후에는 닫힌 제출 버튼이 아니라 필터 열기 버튼으로 초점을 복원한다. 사이드패널 예제의 일괄 적용은 제출 버튼에 유지한다.
- 실제 서버 색인·facet 통계·검색 랭킹·타임존 범위 변환은 미구현이다.
- 즉각 텍스트 검색은 타자마다가 아니라 값 확정(change) 시 반영한다. 쿼리 연산은 두 텍스트 조건의 AND/OR/NOT으로 제한한다.
- 이 파일 작성 시 실제 브라우저 조작 검증은 부모 작업에 인계했다. 자동 규칙/마크업 검사 결과는 `README.md`의 검증 명령과 별도 작업 보고를 확인한다.
