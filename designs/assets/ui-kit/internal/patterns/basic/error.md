# 오류

출처: 행정안전부, 디지털 정부서비스 UI/UX 가이드라인(2024.02), PDF p.626–630. 공공누리 제1유형. [원문 참고](../../reference/krds-p0626.md).

## 재사용 범위

[실행 예제](error.html)는 Altool이 독립 제작한 프런트엔드 조합 예제다. 공식 구현이나 접근성 인증이 아니며 실제 수집·제출·외부 API 호출은 하지 않는다. `basic.css`, `basic-core.js`, `basic.js`를 함께 사용하고 필요한 패턴의 초기화와 DOM만 선택한다. 고객 디자인 원본이 있으면 해당 시각 계약을 우선한다.

### 제공한 상태·변형

- 빈 입력 인라인 오류·aria-invalid·첫오류 포커스
- 연습 서버오류 dialog·닫기 후 입력포커스·값보존

## 원문 적용 체크리스트

다음은 적용 프로젝트에서 확인할 목록이다. 항목 존재/자동 테스트를 전체 의미적 준수로 해석하지 않는다. 부적합 예제·실제 기관 브랜드·개인정보는 기본 자산으로 복제하지 않았다.

- [ ] BP-626-01: 오류를 빠르게 인지할 수 있도록 위치·크기·텍스트를 표현하며 색에만 의존하지 않는다.
- [ ] BP-626-02: 무엇이 어디에서 잘못되었는지 구체적으로 설명한다.
- [ ] BP-626-03: 다음 행동·수정 방법을 제공한다.
- [ ] BP-626-04: 사용자를 탓하지 않는 정중한 문체를 사용한다.
- [ ] BP-626-05: 오류 지점으로 초점을 옮기며 모달을 닫은 후 오류 입력 필드로 복귀한다.
- [ ] BP-626-06: 입력값과 선택을 지우지 않아 수정·재시도가 가능하게 한다.

## 실제 브라우저 재검증 시나리오

1. 빈 제목 확인 → 오류+초점, 값 입력 → 성공
2. 제목 입력 후 서버오류 열기 → Escape/돌아가기 → 값보존·입력포커스
3. 390px/1280px에서 잘림·겹침·포커스·주요 동작·콘솔 오류를 확인한다. 키보드와 실제 스크린리더 확인은 별도이며 정적 마크업 검사로 대체하지 않는다.

## 미적용·잔여 검증

- 오류·재시도·로딩·취소·복구 UI는 `state-variants.html#retry-state`에 제공한다. 네트워크 공통 문구는 `messages/ko.json`의 `error.network` 한 곳에서 읽는다. 실제 오류 분류·추적 ID와 업무 요청 어댑터는 서비스 경계다.
- 이 파일 작성 시 실제 브라우저 조작 검증은 부모 작업에 인계했다. 자동 규칙/마크업 검사 결과는 `README.md`의 검증 명령과 별도 작업 보고를 확인한다.
