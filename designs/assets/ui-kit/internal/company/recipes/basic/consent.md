# 동의

출처: 행정안전부, 디지털 정부서비스 UI/UX 가이드라인(2024.02), PDF p.590–596. 공공누리 제1유형. [참고출처](../../../ATTRIBUTION.md).

## 재사용 범위

[실행 예제](consent.html)는 Altool이 독립 제작한 프런트엔드 조합 예제다. 공식 구현이나 접근성 인증이 아니며 실제 수집·제출·외부 API 호출은 하지 않는다. `../../dist/company.css`와 `../recipes.css`, `basic-core.js`, `basic.js`를 함께 사용하고 필요한 패턴의 초기화와 DOM만 선택한다. 고객 디자인 원본이 있으면 해당 시각 계약을 우선한다.

### 제공한 상태·변형

- 필수+선택 약관, 구조화된 키보드 스크롤
- 전체/개별 선택 양방향 동기화
- 선택 미동의 진행과 필수 미동의 오류

## 원문 적용 체크리스트

다음은 적용 프로젝트에서 확인할 목록이다. 항목 존재/자동 테스트를 전체 의미적 준수로 해석하지 않는다. 부적합 예제·실제 기관 브랜드·개인정보는 기본 자산으로 복제하지 않았다.

- [ ] BP-590-01: 동의하지 않음 대안을 제공한다.
- [ ] BP-590-02: 동의함·동의하지 않음 옵션을 다른 요소와 구분한다.
- [ ] BP-590-03: 필수·선택을 텍스트로 명시하고 필수 항목을 위에 둔다. 선택 미동의로 진행을 막지 않는다.
- [ ] BP-590-04: 약관 스크롤 영역은 키보드로 접근·탐색 가능해야 한다.
- [ ] BP-590-05: 약관 본문은 제목·문단의 의미 있는 구조를 쓴다.
- [ ] BP-590-06: 각 라디오 설명을 해당 약관 제목과 aria-describedby로 연결하고 레이블을 오른쪽에 둔다.
- [ ] BP-590-07: 일괄 선택하면 모두 동의, 해제하면 모두 미동의로 동기화한다. 하나라도 미동의이면 전체 선택을 해제한다.
- [ ] BP-590-08: Tab/Shift+Tab 이동, 체크박스 Space, 라디오 기본 키보드 조작을 보존하고 일괄 선택의 초점을 유지한다.

## 실제 브라우저 재검증 시나리오

1. 전체 동의 체크/해제 → 두 그룹 동기화
2. 전체 체크 후 선택 항목 미동의 → 전체 해제 + 선택 확인 성공
3. 필수 미동의 → 진행 오류 + 첫 필수 옵션 포커스
4. 390px/1280px에서 잘림·겹침·포커스·주요 동작·콘솔 오류를 확인한다. 키보드와 실제 스크린리더 확인은 별도이며 정적 마크업 검사로 대체하지 않는다.

## 미적용·잔여 검증

- 예제 문구는 법적 약관·개인정보 동의가 아니다. 기관별 수집 목적/항목/보유기간/거부권·버전·증거보관은 별도 법무·서버 계약이 필요하다.
- 이 파일 작성 시 실제 브라우저 조작 검증은 부모 작업에 인계했다. 자동 규칙/마크업 검사 결과는 `README.md`의 검증 명령과 별도 작업 보고를 확인한다.
