# 입력폼

출처: 행정안전부, 디지털 정부서비스 UI/UX 가이드라인(2024.02), PDF p.631–650. 공공누리 제1유형. [참고출처](../../../ATTRIBUTION.md).

## 재사용 범위

[실행 예제](form.html)는 Altool이 독립 제작한 프런트엔드 조합 예제다. 공식 구현이나 접근성 인증이 아니며 실제 수집·제출·외부 API 호출은 하지 않는다. `../../dist/company.css`와 `../recipes.css`, `basic-core.js`, `basic.js`를 함께 사용하고 필요한 패턴의 초기화와 DOM만 선택한다. 고객 디자인 원본이 있으면 해당 시각 계약을 우선한다.

### 제공한 상태·변형

- 단일열 필수/선택·단위·오류·처리중·완료
- 탭 메모리 임시저장/복원·모달1필드
- 단계형2단계·이전입력 재사용·뒤로

## 원문 적용 체크리스트

다음은 적용 프로젝트에서 확인할 목록이다. 항목 존재/자동 테스트를 전체 의미적 준수로 해석하지 않는다. 부적합 예제·실제 기관 브랜드·개인정보는 기본 자산으로 복제하지 않았다.

- [ ] BP-631-01: 단일 화면을 기본으로 하되 모달은 적은 필드(권장5개 이내), 단계형은 논리적으로 이어지는 복잡한 입력에 사용한다.
- [ ] BP-631-02: 콘텐츠는 단일 열 중심으로 정렬하고 관련 필드는 묶으며 충분한 간격을 둔다.
- [ ] BP-631-03: 액션 위치/위계를 일관되게 제공한다. 오른쪽 정렬 제출은 가장 오른쪽, 3차 액션은 왼쪽에 둔다.
- [ ] BP-631-04: 미완료 비활성 제출은 상황에 따라 고려하되 처리 중 중복 제출을 방지하고 진행 피드백을 제공한다.
- [ ] BP-631-05: 레이블/설명/단위를 필드 가까이에 두고 필수/선택 표시 방식은 일관되게 제공한다.
- [ ] BP-631-06: 필요한 최소 데이터만 받고 기존 입력 재사용·목적에 맞는 자동완성을 고려한다.
- [ ] BP-631-07: 오류 입력을 자동 삭제하지 않는다.
- [ ] BP-631-08: 모바일·저대역폭·터치 입력에서도 동작하도록 구성한다.
- [ ] BP-631-09: 폼과 각 필드·섹션에 접근 가능한 이름·제목·필수 정보를 제공한다.
- [ ] BP-631-10: 정확한 오류 항목을 알리고 첫 오류로 초점을 옮긴다. 사용자의 자유로운 초점 이동을 막지 않는다.
- [ ] BP-631-11: 단계형에서 같은 정보를 다시 입력하게 하지 않는다.
- [ ] BP-631-12: 클라이언트 확인만 신뢰하지 않고 실제 제출 시 서버 검증을 반드시 병행한다.
- [ ] BP-631-13: 전체값이 필요한 검증은 focusout 이후 수행하고 실시간 규칙 검사는 필요한 필드만 수행한다.

## 실제 브라우저 재검증 시나리오

1. 빈폼 제출 → 첫오류포커스, 부수0/1.5/11 오류→1 성공
2. 가상 제목·부수 임시저장→변경→복원, 제출중 disabled→완료
3. 모달 열기/취소/반영/Escape, 단계1 빈값차단→2→이전 값보존→완료
4. 390px/1280px에서 잘림·겹침·포커스·주요 동작·콘솔 오류를 확인한다. 키보드와 실제 스크린리더 확인은 별도이며 정적 마크업 검사로 대체하지 않는다.

## 미적용·잔여 검증

- 실제 서버 검증·저장·복구·중복 요청 키·권한 검사는 미구현이다.
- 임시 저장은 탭 메모리뿐이고 새로고침하면 사라진다. 운영 임시 저장이라고 표시하면 안 된다.
- 일반 제목/부수는 개인정보가 아니므로 이름/연락처 autocomplete는 비적용이다. identity 예제에 제공한다.
- 이 파일 작성 시 실제 브라우저 조작 검증은 부모 작업에 인계했다. 자동 규칙/마크업 검사 결과는 `README.md`의 검증 명령과 별도 작업 보고를 확인한다.
