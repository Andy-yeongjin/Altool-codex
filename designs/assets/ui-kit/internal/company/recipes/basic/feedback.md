# 사용자 피드백

출처: 행정안전부, 디지털 정부서비스 UI/UX 가이드라인(2024.02), PDF p.602–611. 공공누리 제1유형. [참고출처](../../../ATTRIBUTION.md).

## 재사용 범위

[실행 예제](feedback.html)는 Altool이 독립 제작한 프런트엔드 조합 예제다. 공식 구현이나 접근성 인증이 아니며 실제 수집·제출·외부 API 호출은 하지 않는다. `../../dist/company.css`와 `../recipes.css`, `basic-core.js`, `basic.js`를 함께 사용하고 필요한 패턴의 초기화와 DOM만 선택한다. 고객 디자인 원본이 있으면 해당 시각 계약을 우선한다.

### 제공한 상태·변형

- 감정2선택·선택 추가질문2개·건너뛰기
- 완료 메시지·5점 별도 대안

## 원문 적용 체크리스트

다음은 적용 프로젝트에서 확인할 목록이다. 항목 존재/자동 테스트를 전체 의미적 준수로 해석하지 않는다. 부적합 예제·실제 기관 브랜드·개인정보는 기본 자산으로 복제하지 않았다.

- [ ] BP-602-01: 특정 화면·기능 경험에 사용하며 전체 서비스 다문항 설문은 별도 화면으로 구성한다.
- [ ] BP-602-02: 평가는 본문 하단이나 충분한 너비의 사이드 영역에 둔다. 모바일은 하단으로 두고 플로팅 버튼으로 축약하지 않는다.
- [ ] BP-602-03: 시의적 평가를 요청한다면 이용 완료 후 요청하고 페이지 로딩 직후 방해하지 않는다.
- [ ] BP-602-04: 최초 질문은 폐쇄형, 감정 선택은 가능한 2개, 별점은 5개 이내로 둔다.
- [ ] BP-602-05: 추가 질문은 최대 3개, 마지막에 선택적 자유 의견을 두며 응답 없이 완료할 수 있게 한다.
- [ ] BP-602-06: 각 질문/입력에 이름을 제공한다.
- [ ] BP-602-07: 추가영역과 완료메시지는 polite live region으로 알린다.
- [ ] BP-602-08: 평가 버튼에서 Enter/Space/클릭하면 추가영역을 열거나 완료 메시지를 표시하고 선택 직후 초점은 버튼에 둔다.
- [ ] BP-602-09: 추가영역은 순서대로 Tab 이동하며 건너뛰기·완료 모두 평가 완료를 안내한다.

## 실제 브라우저 재검증 시나리오

1. 도움이 됐어요 → 추가질문 표시/선택 초점 유지 → 의견 없이 완료
2. 새로고침 후 아쉬웠어요+가상 의견 → 평가 완료/전송없음
3. 별점1/5 → aria-pressed와 완료 메시지
4. 390px/1280px에서 잘림·겹침·포커스·주요 동작·콘솔 오류를 확인한다. 키보드와 실제 스크린리더 확인은 별도이며 정적 마크업 검사로 대체하지 않는다.

## 미적용·잔여 검증

- 실제 응답 수집·분석·중복 방지·보존은 미구현이다.
- 감정 평가와 별점이 한 페이지에 있는 것은 두 유형 비교 목적이다. 실제 화면에는 한 가지를 선택한다.
- 이 파일 작성 시 실제 브라우저 조작 검증은 부모 작업에 인계했다. 자동 규칙/마크업 검사 결과는 `README.md`의 검증 명령과 별도 작업 보고를 확인한다.
