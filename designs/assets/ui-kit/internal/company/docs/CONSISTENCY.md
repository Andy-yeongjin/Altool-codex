# 전사 일관성 규칙 · v27

이 문서는 업무 화면을 만드는 AI와 개발자의 조합 기준입니다. 승인된 색·버튼·아이콘·모서리·폰트는 GUIDE.md를 따릅니다.
아래 배치 및 행동은 신규 화면의 기본값입니다. 기존 운영 화면을 변경할 때는 업무 영향과 사용자 흐름을 확인합니다.

## 고정할 것과 업무별로 정할 것

| 공통 고정 | 업무별 결정 |
|---|---|
| Pretendard 및 대체 폰트, 입력·버튼 규격 | 조회항목 종류·개수·기본값 |
| 주요 파랑 #1554A0, 상단 #18334F | 법인별 접근 범위·업무 상태 전이 |
| 라벨·값·오류·비활성 표현 | DB/API 호출, 조회 시점의 기준일 |
| 버튼 역할, 동일 영역의 간격·정렬 | 필수값·금액 한도·수정 가능 조건 |
| 팝업 닫기·포커스 복귀 방식 | 저장·승인·취소의 실제 처리 |
| 날짜·금액·빈값 표시 방법 | 금액 반올림·회계 의미·통화 환산 |

## 화면 유형별 구성

1. 조회형: 페이지 제목 → 조회조건 → 조회·초기화 → 결과 요약 → 표 도구 영역 → 표 → 페이지 이동.
2. 등록·수정형: 페이지 제목 → 오류 요약 → 항목 그룹 → 첨부 → 취소·저장.
3. 목록·상세형: 조회형 구성 + 행의 보기 버튼 → 상세 패널. 선택 체크박스와 상세 열기를 분리.
4. 대시보드형: 페이지 제목 → 조회조건 → 지표 요약 → 차트 → 상세 표. 차트마다 별도 임의 카드 스타일을 만들지 않음.

전체 페이지의 열 개수나 카드 개수를 고정하지 않습니다. 각 유형의 조합 예제는 `docs/PAGE-PATTERNS.md`에 있습니다.

## 버튼·입력

- 조회조건 영역은 조회(파랑), 초기화(기본) 순. 초기화는 빈칸 전체가 아니라 해당 화면의 명시된 초기값 복원.
- 편집 폼 하단은 취소(기본), 저장(파랑) 순으로 오른쪽 정렬. 삭제는 저장 바로 옆에 섞지 않고 별도 작업 영역에 배치.
- 표 전체 작업과 선택 행 작업을 구분. 선택 없는 승인·반려는 비활성. 전체 선택의 범위를 문구로 표시.
- 주요 버튼의 아이콘은 선택 사항. 사용할 때 Lucide120개+Altool13개의 회사133개 카탈로그에서 의미 ID로 선택하며 아이콘 유무로 버튼 높이를 바꾸지 않음.
- 같은 폼 내 라벨 위치·입력 높이·행 간격을 통일. 긴 라벨은 줄바꿈 허용. 코드·명칭은 항상 같은 순서.
- 단일/다중 선택 목록은 입력창과 외곽 너비를 맞춤. 달력과 코드 검색 모달은 콘텐츠에 필요한 별도 규격 사용.
- 필수 여부는 색만으로 표시하지 않고 '필수' 문구 제공. placeholder는 라벨 대체 불가.
- 읽기 전용 값은 읽고 복사할 수 있게 유지. 사용 불가(disabled)와 읽기 전용(readonly)을 구분.

## 값·용어·상태

| 항목 | 기본 규칙 |
|---|---|
| 날짜 | YYYY-MM-DD |
| 월 | YYYY-MM |
| 일시 | YYYY-MM-DD HH:mm, 시간대는 데이터 계약에 명시 |
| 금액 | 천 단위 쉼표, 표에서는 제목·본문 모두 가운데 정렬(ui-number 포함), 표 제목/열 제목에 통화·단위. 입력 필드·차트는 해당 컴포넌트 정렬 유지 |
| 음수 | 앞쪽 마이너스. 빨강은 보조 표현이며 값의 기호를 생략하지 않음 |
| 0 / 빈값 | 0은 `0`, 값 없음은 `—` |
| 코드 | 선행 0 유지. 숫자 변환하지 않음 |
| 퍼센트 | 기본 소수 1자리 제안, 화면 내 동일 기준 적용. 분모 0은 '계산 불가' |
| 대기 | neutral, 아직 시작하지 않음 |
| 진행 | progress, 처리가 진행 중 |
| 완료 | success, 정상 완료 |
| 반려 | error, 요청이 수용되지 않음. 시스템 오류와 문구로 구분 |
| 취소 | neutral, 사용자/업무 취소. 삭제와 혼용하지 않음 |

`B.formatNumber`는 화면 포맷용입니다. 금융 계산은 서버 또는 승인된 십진 연산 방식으로 처리하며 JS Number의 정밀도를 넘는 정수·금액에 사용하지 않습니다.
표준 용어는 업무가 다르면 별도 상태 매핑표로 명시하고 임의의 비슷한 상태명을 추가하지 않습니다.

## 동작·피드백

- DB 조회형 화면은 조회 버튼으로 일괄 반영을 기본으로 제안. 입력 중 조건과 적용된 조건을 혼동하지 않게 표시.
- 저장 요청 중 중복 실행 차단. 성공 응답 전 '저장 완료'를 표시하지 않음.
- 오류 시 입력 유지. 폼 오류는 요약+해당 필드, 통신 오류는 지속 안내와 재시도.
- 부분 성공은 성공 N건·실패 M건과 실패 항목을 표시. 전체 실패나 전체 성공으로 뭉뚱그리지 않음.
- 완료 알림은 오른쪽 아래에 일관되게 표시. 중요한 오류·필수 조치는 자동으로 사라지는 알림만 사용하지 않음.
- 미저장 변경이 있으면 화면 이탈 확인. 저장 중 추가 편집을 이미 저장된 것으로 처리하지 않음.
- 모달·패널의 Esc는 가장 안쪽 열린 요소부터 닫고 열기 위치로 포커스 복귀.
- 조직 탐색은 native disclosure 목록. 완전한 ARIA tree라고 표현하지 않음.

## 폰트·배포·AI 작업 규칙

- 사내 승인 정적 경로에서 Pretendard를 로드. 시스템마다 다른 외부 CDN을 임의로 추가하지 않음.
- AI는 회사 registry의 의미 ID를 선택한 뒤 [요소 진입점](../components.json)을 통해 [업무 API](BUSINESS-USAGE.md), [보완 컴포넌트](../extensions/README.md), [레시피](../recipes/README.md) 중 해당 계약을 읽음. 비슷한 CSS·JS를 화면 안에 복제하지 않음.
- extensions24개 ID·37변형과 recipes18개 ID·90변형은 같은 v27의 기능 보완이며 별도 디자인 선택지가 아님. 이전 정부 UI의 실행 코드·외형으로 대체하지 않음. 정부 자료는 지침·출처로만 참고.
- 데이터 예제를 업무 규칙으로 사용하지 않음. 예제 메모리 저장을 실제 서버 저장이라고 표현하지 않음.
- 네트워크·권한·저장은 앱 adapter가 담당. 공통 자산에는 환경별 주소·토큰·사원정보를 하드코딩하지 않음.
- 버전 고정 후 사내 배포. 공통 클래스/함수 변경 시 사용 화면을 확인하고 API 변경을 기록.
- 기본·선택·비활성·오류·조회 중·결과 없음과 긴 텍스트·좁은 화면·키보드 이동을 사용 앱에서 점검.
- 현재 팩의 실제 브라우저 점검은 접근 정책 차단으로 미완료. 정적·모델·DOM 대역 검사와 과거 디자인의 QA 기록을 현재 화면 검증으로 환산하지 않음.

## v27 · 조회조건 조합 규칙
- 조회조건 하나당 라벨 하나 + 입력창 하나. 기간 위에 별도의 라벨을 쌓지 않고 '승인 시작일', '승인 종료일'로 구분합니다.
- `ui-filter-bar` 안에 `ui-field`를 나열하고 조회·초기화는 `ui-filter-actions`로 묶습니다.
- 기간 검증용 컨테이너는 `ui-filter-range`로 묶습니다. display:contents로 내부 필드가 같은 행 배치에 참여합니다.
- 라벨 높이 21px, 라벨과 입력 간격 6px, 필드 간격 16px. 입력·단일 선택·달력 입력의 공통 높이를 사용합니다.
- 긴 라벨이 2줄이면 조회조건 컨테이너의 `--company-filter-label-height:42px`로 전체 라벨 예약 높이를 맞춥니다.
- 오류 안내는 전체 너비의 별도 행에 표시하여 입력창 기준선을 이동시키지 않습니다.
- 공간이 좁으면 항목이 줄바꿈되며, 모바일에서 작업 버튼은 별도 행으로 내려갑니다.
- 이 규칙은 가로 조회조건용입니다. 모니터링의 세로 조회조건이나 등록 폼에 자동 적용하지 않습니다.
