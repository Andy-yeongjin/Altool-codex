# 사내 공통영역 접근 표준

<a id="authorization"></a>
## 서버 권한

- 필수 ACC-01: 보호된 조회·변경·내보내기·업로드는 서버에서 사용자·작업 권한을 검사한다. 메뉴 숨김은 보안 검증을 대신하지 않는다.
- HTTP 메서드만으로 권한을 정하지 않는다. 비밀번호 초기화·권한 편집·엑셀 UPSERT는 실제 작업과 대상별 권한을 검사한다. 알 수 없는 권한·범위는 거부한다.
- 검증: UI 우회 직접 API 호출과 비허용 역할의 변경·내보내기 거부를 확인한다.

<a id="data-scope"></a>
## 데이터 범위

- 필수 ACC-02: ALL/DEPT/SELF를 목록뿐 아니라 단건 조회·수정·삭제·엑셀 작업에도 적용한다. DEPT는 승인된 기준 부서와 하위 조직, SELF는 계약에서 정한 소유자를 사용한다.
- 엔티티별 범위 컬럼을 명시한다. 과거 업무 데이터는 data.md의 작성 시점 소속 계약을 적용하고 현재 사용자 부서로 과거 소유권을 재계산하지 않는다.
- 검증: 타 부서 레코드 ID 직접 접근, 목록·상세·업로드 간 범위 차이를 검사한다.

<a id="authentication"></a>
## 인증 경계

- 필수 ACC-03: 비활성·삭제·잠김 사용자와 무효 세션은 보호 작업에 접근할 수 없다. 비밀번호 변경 강제 상태에서는 허용한 변경·로그아웃 외 작업을 제한한다.
- 세션 만료·폐기·권한 변경 반영, 쿠키 속성, CSRF 방어, 비밀번호 해시·잠금·초기화 정책은 인증 Spec에 명시한다. 값은 기능 PRD에서 결정하며 예제의 숫자를 전역 정책으로 복사하지 않는다.
- 검증: 초기 비밀번호 상태의 API 우회, 로그아웃/계정 비활성 후 기존 세션 접근을 확인한다.
