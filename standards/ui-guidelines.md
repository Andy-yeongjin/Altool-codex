# 회사 UI 작업별 지침

Altool 기본 회사 계약이다. 도입 전 회사 디자인과 업무에 맞춰 조정하고 사내에 동일 배포한다. KRDS는 참고 근거이며 원문 전체가 자동으로 회사 규칙이 되지 않는다. 아래 조건부 항목은 존재하는 기능에 적용하며 기능을 새로 추가하라는 뜻이 아니다.

<a id="common"></a>
## 공통 진입·조합·검증

- UI-01: 요청의 화면/과업/상태를 먼저 분류한다. 로그인·검색·폼·상세·내비게이션·신청 등 해당 세부 태그를 ui-create/change/review와 함께 선택하고, 미분류 작업은 활성 표준을 넓게 읽어 관련 항목을 확정한다. 자산 후보는 강제 사용 목록이 아니다.
- UI-02: 화면의 주요 과업·정보 위계·데스크톱/모바일 순서를 Spec에 정하고 해당 패턴과 부품을 조합한다. 공통 팩의 회사 적용 지침·constraints·선택 states를 읽고 같은 의미의 자산을 재사용한다. 참고 예제의 모든 컨트롤이나 모의 데이터를 그대로 앱에 넣지 않는다.
- UI-03: 실제 코드/화면과 변경 목록을 독립 대조하여 빠진 공통 의미, 임의 대체, 잘못된 작업 태그 및 기능 전용/비적용 판단을 확인한다. 선택한 지침별 테스트/관찰에는 명세의 글자·간격·화면 밀도, 축소 후 차트 글자, 아이콘 방향의 실제 측정값을 연결한다(`tooling/README.md#ui`); 클릭 성공·파일 hash만으로 표시 준수를 대체하지 않는다. 회사 필수 계약 충돌은 N/A로 면제하지 말고 공통 변경의 영향과 승인 범위를 해결한다.
- UI-04: 사용자 목표·빈도·난이도와 방문→찾기→이해→수행→종료 중 관련 여정을 정의한다. 조직 내부 구조만으로 화면을 나누지 않고, 단계 수를 줄이더라도 필요한 확인·복구를 제거하지 않는다.
- UI-05: 장애·고령·언어·일시적 제약을 포함해 어려움이 큰 이용 조건을 먼저 확인한다. 초보자와 숙련자에게 필요한 도움·선택 가능한 고급 기능을 과업에 맞게 제공하되 이용 흐름과 자율성을 방해하지 않는다.
- UI-06: 익숙한 용어·예측 가능한 조작·논리적 순서를 사용한다. 정보의 정확성과 최신성을 확인하고 지연된 정보는 갱신 예정과 함께 설명한다. 발견한 사용성 문제는 영향도와 개선 항목으로 남긴다.

<a id="form"></a>
## 입력·업로드

- FORM-01: 단일 화면/단계형/모달을 입력 규모와 논리적 순서로 선택한다. 필드 묶음·레이블·도움·필수/선택·오류 위치와 액션 위계를 선택한 회사 패턴에 맞춘다.
- FORM-02: 해당되는 입력 오류·값 보존·첫 오류 초점·처리 중 중복 제출 차단·완료/실패를 실제 동작으로 확인한다. 업로드가 있으면 조건 안내와 선택/삭제/재시도 및 서버 검증 경계를 확인한다.

<a id="auth"></a>
## 로그인·세션

- AUTH-01: 앱에서 실제 지원하는 인증 방식만 제공한다. 입력·비밀번호 표시·도움·인증 실패·세션 만료 후 복귀 흐름을 회사 인증 패턴과 연결한다. 예제 인증 성공을 실제 인증으로 사용하지 않는다.
- AUTH-02: 사용자에게 제공한 인증/세션 경로를 실제 통합 테스트로 검증한다. 비밀번호/인증값 노출, 실패 시 입력 보존 범위, 로그아웃·만료 후 보호 경계를 함께 확인한다.

<a id="search"></a>
## 검색·목록·필터

- SEARCH-01: 데이터 규모에 맞는 검색/필터/정렬/페이지 이동만 선택한다. 조건·결과 수·현재 페이지·빈 결과/오류 표시와 상세 이동 후 복귀 상태를 정한다.
- SEARCH-02: 실제 조건 변경·해제·정렬·페이지/상세 이동으로 표시 데이터와 초점/알림을 검증한다. 모바일에서도 조건과 핵심 정보를 잃지 않는다.

<a id="content"></a>
## 방문·상세·내비게이션·도움

- CONTENT-01: 주요 과업부터 정보 계층과 메뉴/목차/본문/도움 영역을 정한다. 선택 컴포넌트의 화면 폭별 배치, 제목 일치, 실제 목적지와 초점 이동을 적용한다. 중요한 안내를 접힌 영역에만 숨기지 않는다.
- CONTENT-02: 실제 링크·목차·첨부·도움/피드백의 제공 경로를 조작하고 제목/대체 설명/좁은 화면의 순서를 확인한다. 정부 식별자·샘플 회사 CI를 실제 회사 식별자로 오인하지 않는다.

<a id="transaction"></a>
## 신청·예약·발급·내역

- TRANSACTION-01: 안내→입력→확인→완료/내역 중 실제 과업의 단계를 선택한다. 이전 단계 입력, 취소/복귀, 처리 상태와 결과의 관계를 보존한다. 되돌리기 어려운 행동은 결과를 설명하고 확인한다.
- TRANSACTION-02: 실제 저장/조회/예약 충돌/실패/재시도 및 권한 경계를 앱 통합에서 검증한다. 데모 데이터·지연·가상 발급 결과를 운영 처리 완료로 보고하지 않는다.
