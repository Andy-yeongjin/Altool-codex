# 사내 공통영역 일괄 입력 표준

<a id="validation"></a>
## 공통 검증

- 필수 IMP-01: 공통 엔진과 엔티티 정의를 사용한다. 정의는 서버에 등록된 대상·키·허용 필드·검증·권한을 지정하며 임의 테이블명이나 클라이언트 정의로 쓰기를 실행하지 않는다.
- 필드 키는 앱/ORM camelCase로 통일하고 DB 이름 매핑은 schema.md를 따른다. 형식, 참조·활성 여부·순환, 파일/DB 중복을 검증한다. 같은 파일 내부의 상위 조직 참조도 지원 여부를 명시한다.
- 정의만으로 표현할 수 없는 업무 규칙은 공통 엔진을 우회하지 않는 검증/저장 확장점으로 연결하고 테스트한다.

<a id="commit"></a>
## 확정과 감사

- 필수 IMP-02: 오류가 있으면 전체 미반영한다. UI 버튼 비활성뿐 아니라 서버 확정 요청에서도 권한·범위·입력·참조를 재검증한다. 미리보기 이후 데이터 변경과 요청 재전송을 처리한다.
- 필수 IMP-03: 업무 변경과 감사는 같은 트랜잭션에 넣고 동일 batch_id로 연결한다. 실패 업로드 이력은 롤백 이후 별도 기록하여 실패 사실이 사라지지 않게 한다.
- 행 수·파일 크기·실행 시간 한계는 제품 Spec에서 정하고 최대 허용 배치로 검증한다. 대량 처리 때문에 전건 원자성을 조용히 부분 반영으로 바꾸지 않는다.
- 검증: 오류 1행, 확정 API 직접 호출, 권한 변경, 중간 실패, 재전송 시 중복 반영을 확인한다.

<a id="parsing"></a>
## 파일 파싱

- 필수 IMP-04: 식별자 텍스트 형식, 날짜 변환, 헤더, 빈 행, 공백 처리 규칙을 템플릿과 파서에 일치시킨다. 숫자 셀에서 이미 사라진 앞자리 0을 raw:false만으로 복구한다고 가정하지 않는다.
- 오류 파일·다운로드에 원문 비밀값을 넣지 않고 사용자 입력이 스프레드시트 수식으로 실행되지 않도록 처리한다. 파서·파일 형식·보안 업데이트는 실제 도입 버전으로 검토한다.
