# 사내 공통영역 데이터 표준

<a id="lifecycle"></a>
## 데이터 수명

- 필수 DATA-01: 등록된 마스터·권한 매핑·업무 엔티티는 del_yn 논리삭제를 사용한다. 조회·참조 검증·유일성·재활성화 정책을 함께 설계한다. 세션·임시 작업·로그 아카이브는 별도 수명 정책을 따르며 전 테이블 물리삭제 금지로 확대하지 않는다.
- 공통 감사 컬럼은 del_yn, created_by, created_at, updated_by, updated_at이며 시스템 작업의 행위자도 명시한다. append-only 로그에는 수정·논리삭제 컬럼을 강제하지 않는다.

<a id="audit"></a>
## 감사 원자성

- 필수 DATA-05: 감사 로그(log_audit 계열)는 append-only이며 레코드 수정·삭제 API/일반 업무 경로를 제공하지 않는다. 보관 종료 이관·파기는 회사가 확정한 별도 승인 절차와 권한·실행 기록을 따른다. 접속 로그 전체에 자동 확대하지 않는다. 소비 앱은 변경 API 거부·권한 우회·보관 절차 경계를 검증한다.
- 필수 DATA-02: 감사 대상 변경과 감사 레코드는 함께 커밋·롤백된다. 생성·수정·논리삭제·UPSERT·일괄 변경 등 실제 지원 쓰기 경로를 모두 포함한다.
- 필수 DATA-03: 공통 데이터 접근 경계에서 누락 없이 기록한다. Prisma extension은 예시이며 동일 트랜잭션 참여·일괄 쓰기·중첩 쓰기·재귀 방지를 검증한 구현을 채택한다.
- 실제 변경 필드만 기록하고 감사 메타데이터만 바뀐 경우 업무 diff를 만들지 않는다. password_hash와 비밀값은 전후 값 모두 제거/마스킹한다. 논리삭제 전이는 DELETE로 기록한다.
- 행위자·요청·유입경로·batch_id는 서버 요청 경계에서 전달한다. 클라이언트가 제공한 행위자 정보를 신뢰하지 않는다. 로그 필드명은 DB 이름으로 통일하고 복합키는 충돌 없는 구조로 직렬화한다.
- 검증: 의도적 실패 시 원본·감사 모두 롤백, 무변경 저장, 민감값 부재, 각 쓰기 경로의 누락을 확인한다. 조직 스냅샷을 요구하는 기능은 동일 트랜잭션에 포함한다.

<a id="ownership"></a>
## 작성 시점 소속

- 필수 DATA-04: 소속 기반 접근이 필요한 biz_ 데이터에는 작성 시점 부서를 저장한다. 조직 이동 후 과거 데이터 접근 기준은 해당 snapshot을 사용하며, 재귀 조직 범위와 결합하는 방법을 Spec에 명시한다.
- 보관기간·아카이브·이력 시점 조회는 제품 계약으로 확정한다. 시각 저장·전송·표시 경계는 constitution.md를 따른다.
