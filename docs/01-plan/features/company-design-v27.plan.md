## 최초 승인 범위 (아래 후속 승인으로 호환 보존 방침 대체)

사용자 제공 company-design-v27을 Altool 기본 회사 디자인으로 채택한다. 디자인 두 CSS, 공통 JS·아이콘·업무 조합 지침을 기존 팩/라우터/설치에 통합한다. 원본 폴더, upstream·출처 자료, 헌법, 기존 테스트 앱은 보존한다. 새로운 회사 팩 QA 버전으로 발행하며 기존 설치 앱을 자동 업그레이드하지 않는다.

## 순서와 성공 기준

1. design/ 두 CSS 교체, internal/company에 업무 코드·아이콘 원본·문서·미리보기 통합. 재빌드가 모든 배포본과 미리보기로 전파되고 --check는 stale을 거부한다.
2. 중복 의미는 기존 ID의 회사 기본 변형을 v27로 교체하고 이전 변형은 호환용으로 표시한다. 추가 의미는 registry와 guidance에 등록하고 라우터로 찾는다. 기존 ID를 조용히 없애지 않는다.
3. 공통 메시지는 기존 ko.json을 단일 원본으로 유지한다. v27 런타임에 필요한 문구를 키로 생성/참조하며 UI 데이터·업무 정책과 구분한다.
4. 팩 무결성·CSS 사전검사·설치·기존 회귀·v27 회귀를 수행한다. 실브라우저 미실행을 코드 검사 통과로 대체하지 않는다.

## 적용 판단

code-change/ui-change/form-ui/search-ui/navigation-ui/history-ui/upload-ui/dashboard-ui. 제품 제작 Python/프레임워크 중립 JS 작업으로 internal-stack 비적용: 사내 DB·권한 시스템 구현 요청이 아니다. 디자인 공통 승인 원천은 v27이며 화면별 PRD/Spec의 완성을 의미하지 않는다. 표준/지침 규칙과 실제 파일·회귀는 Spec에서 연결한다.

## 보존 경계

UI Kit 최상위 README.md/design/internal 유지. legacy CSS와 v27 company.css를 같은 화면에 중복 로드하지 않는다. 기존 루트 UI 검증 게이트의 의미·해시·필수 증거는 약화하지 않는다. R3-03 부분 재검증 보류 유지. 브라우저 로컬 파일 정책 차단을 우회하지 않는다.

## 후속 승인: v27 단일 실행 자산 (2026-09-10)

사용자가 호환 UI 보존 방침을 명시적으로 변경했다. 빠진 기능을 v27 외형으로 보완한 뒤 정부 디자인 실행 자산을 모두 제거한다. 기존 동작 코드 중 Altool 독립 제작 모델·상태 처리는 이식할 수 있지만 이전 CSS·공식 마크업·정부 아이콘을 실행 의존성으로 남기지 않는다. 사용자 전달 company-design-v27 자체와 기존 테스트 앱은 수정·삭제 대상이 아니다.

1. 22개 미대체 component/pattern/foundation + 서비스 조합6종, 모든 기존 기능 변형과 구형 아이콘 연결을 대조한다. 누락 UI·상태는 v27 테마·동작 계약으로 보완한다.
2. 디자인 CSS 원본2개 → company 배포본 한 경로. 기존 미러 CSS·upstream·정부 예제·생성기 제거. 정부 지침 MD·원문 대조 JSON·라이선스는 실행 불가능한 참고 자료로 보존한다.
3. 모든 의미 ID의 실행 path/dependencies가 새 회사 자산만 가리키게 한다. 이전 variant 이름을 유지하더라도 같은 회사 구현을 가리켜야 하며 구형 경로 fallback은 금지한다.
4. registry/catalog/설치/가이드·회귀를 함께 바꾸고 부정 테스트로 구형 실행 경로 재유입을 차단한다. 호환 경로 제거는 breaking 2.0.0 QA 후보로 기록한다.
5. 파일 제거 전 정확한 목록을 기록하고 추적 파일은 Git, 미추적 생성물은 작업 외부 임시 백업으로 복구 가능하게 한다. 기능 대응과 정적 회귀 후 제거하고 최종 검사한다. 실브라우저 차단은 유지하며 최종 시각 승인을 주장하지 않는다.

사용자가 서브에이전트 분담을 승인했다. 레시피·서비스, 누락 컴포넌트, 독립 회귀 검사를 나누고 주 에이전트는 생성기·등록·제거·설치·문서 통합을 담당한다.

## 번호형 검토 화면 요청

후속 승인: 사용자가 KRDS 원문 PDF·추출 참고자료의 보관 방침을 폐기했다. reference/ 전체와 원문 전용 coverage/source-review 기록·생성기를 제품에서 제거하며, 실행 회사 자산·회사 적용 guidance·출처/라이선스 고지는 유지한다. registry/map의 원문 참조를 비우고 카탈로그/예제/문서의 죽은 연결을 제거한다. 삭제 대상은 회수 가능한 외부 임시 위치로 이동하며 실제 UI 동작 회귀와 새 설치 검사를 보존한다.

후속 승인(38·42번): 전체 선택은 별도 상단 행, 개별 체크 항목은 세로 목록과 실제 라벨 간격으로 구성한다. 이미지 최적화의 파일 선택/목록/삭제/검증도 CompanyBusiness.attachments 단일 선택으로 연결한다. 이미지 변환·원본 보존을 유지하고 삭제/폼 reset/비동기 작업 중 선택 교체/해제 시 결과와 URL 정리를 검증한다.

후속 승인(32번·정책 자료 탐색): 표 제목은 공통 section header로 표 바깥 위에 배치하고 표/스크롤 영역의 접근성 이름을 연결한다. 정책 자료 탐색은 액션 행, PDF 참고 링크는 그 아래 별도 안내 행으로 분리한다. 목적지·검색/목록 동작은 유지하며 생성물과 회귀를 갱신한다.

### 추가 수정 승인 (33·39·40/41·45·60·65번)

페이지 직접 이동은 라벨/입력/이동을 같은 행에 배치하고 좁은 폭에서는 묶음 단위로 줄바꿈한다. 45번과 60번 툴바는 입력 하단 기준으로 버튼을 맞추고 60번 aside는 세로 필터 변형을 사용한다. 39번 헤더는 승인된 브랜드/메뉴 클래스와 흰색 글자·포커스를 연결한다. 40/41번은 기존 CompanyBusiness.attachments를 확장·재사용하여 선택/검증/삭제/초기화 기능을 보존한다. 사용자가 승인한 공통 변경으로 버튼형 링크는 파란 채움 없이 파란 글자로 표시하고 실제 주요 동작 button의 채움은 유지한다. 소스·생성물·관련 문서·회귀를 동기화하고 실제 브라우저 검증은 별도로 보고한다.

후속 사용자 지적·수정 승인: 정책 검색 등 이식 화면의 inline 라벨과 native select 미연결을 수정한다. 공통 ui-field/filter-bar/CompanySelect를 사용하고 DOM 교체·프로그램 값 변경·reset·숨김/표시·제거 시 생명주기를 검증한다. 번호형 아이콘은 공통16px 표시로 고치고 검토용 사각 외곽선을 제거한다. 120개 원본·13개 추가 SVG의 도형 자체는 이 변경에서 바꾸지 않는다. 업무 모델·인증·저장 정책은 유지한다.

추가 아이콘13개와 보완 컴포넌트37변형, 이식 레시피18개 그룹을 루트 `company-additions.html` 한 화면에서 번호로 지칭하게 한다. 기존 자산을 재사용하고 제품 팩·디자인 계약은 바꾸지 않는다. 생성기는 원본 순서와 의미 ID를 보존하며 개수·번호 연속성·경로·JS 구문·재생성 일치를 검사한다. 실제 브라우저 정책 차단은 우회하지 않으며 검증 미완료를 표시한다.

# 표 정렬·행 제목 공통화 · 2026-09-11

사용자가 대시보드 시안을 승인하여 공통 기본값으로 확정했다. V27-S05: 제목·본문 전체 가운데 정렬(ui-number 포함), 회색 배경은 thead에만 적용, tbody 행 제목 의미는 유지하고 기본 배경은 투명. 선택/hover/줄무늬는 th와 td에 동일 적용하며 tfoot 합계 강조는 보존한다. 폼과 차트 숫자 정렬은 범위 밖이다. CONSISTENCY의 금액 오른쪽 정렬 문구는 표/폼으로 구분하여 동기화한다. 대시보드 임시 CSS를 제거한 상태에서 표시·정렬·선택을 검증한다. 기존 CHANGELOG-LEGACY는 현재 지침이 아닌 과거 기록으로 유지한다. internal-stack은 데이터/인증 변경 없는 공통 표 시각 변경이므로 비적용이다.
