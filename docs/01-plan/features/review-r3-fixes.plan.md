## 성공 기준

- OS 메타데이터는 설치되지 않고 실제 뜻밖의 UI Kit 파일은 구조 검사에서 거부된다.
- 선택 규칙의 종류·ID·표 근거를 보존하고 기존 UI 필수 계약을 강등하지 않는다.
- 비활성 후보 판단 누락은 실패하며 정상 비적용·빈 선택은 허용한다. 적용 결정은 활성화 후 재선택해야 한다.
- 제품 게이트는 회사 편집 영역의 비교기에 의존하지 않는다.
- 검사 범위와 사전검사 출력, 감사 계약, v3 대조표, 라이선스 색인, CSS 보장 문서가 실제 코드와 일치한다.
- 기존 제품 개발 기록은 현재 증거로 분류하며 과거 Step Check를 만들어 내지 않는다.
- 좁은 회귀 및 전체 Python/Node 검사 후 같은 Claude 세션으로 재검수한다. Windows 실실행·실브라우저·완주 실험은 별도 미검증으로 남긴다.

## 적용 판단

code-change/terminology-change로 engineering·glossary를 읽었다. 설치 엔진은 Python이므로 생태계 명명을 유지한다(APP-01). 비교기는 기존 JS 순수 함수의 소유 경계만 옮긴다(ENG-06). internal-stack은 기존 Python/Node 제품 도구에 DB 웹앱 스택을 추가하는 요청이 아니므로 비적용이다. 감사/스키마 원문은 제품 템플릿 수정의 근거로 읽되 사내 관리 프로필을 제품 저장소에 강제 활성화하지 않는다.
