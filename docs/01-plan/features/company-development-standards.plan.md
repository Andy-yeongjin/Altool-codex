# 사내 공통 개발 표준 정리 Plan

> 현재 문서 분류·검증 한계: [제품 문서 상태 색인](../../verification-status.md). 아래 과거 기록은 당시 실행 범위이며 최신 Altool 완료 판정을 대신하지 않는다.

상태: 구현·로컬 검증 완료 · 2026-09-08

## 목표와 범위

Altool은 사내 배포 상품이다. 공통영역 v3에서 앱 간 일관성을 만드는 개발 계약은 기본 프로필에 두고, 사용자·조직·역할 관리 시스템을 만드는 기능은 선택형 PRD로 구분한다. 원본 문서·헌법·QA8 디자인 팩·기존 설치본은 변경하지 않는다.

## 결정

- 기술 스택은 기본값이다. 사내라는 이유만으로 PostgreSQL·인증·관리 화면을 모든 앱에 추가하지 않는다.
- 명명/용어/코드 경계는 코드 작업, DB 규칙은 스키마 작업, API/오류 코드 규칙은 API 작업에 읽는다. 전체 원문을 매번 로딩하지 않는다.
- 공통 관리 기반의 접근·감사·일괄 입력은 internal-common 선택형 계약을 유지한다. 기본 헌법의 보안·권한 요구는 비활성화되지 않는다.
- 구체 인증 수치·행 수·보관기간은 PRD/Spec에서 확정할 후보다. 위험한 원문 예제는 그대로 복제하지 않는다.
- 규칙에 맞는 린트 설정을 설치용 standards 하위에 제공한다. 기존 고객 설정을 자동 덮어쓰거나 상품 원본의 Python/vendor 파일을 일괄 개명하지 않는다.

## 성공 기준

1. 기본 코드/API/스키마 작업에 필요한 계약이 라우팅되고 불필요한 DB·인증 의무는 선택되지 않는다.
2. 단어사전·DB 제약 명명·앱 접미어/동사·API 응답/오류 코드와 원문 각 장의 처리 위치를 찾을 수 있다.
3. 실제 ESLint에서 정상/위반/프레임워크 예외 fixture를 검증한다.
4. 새 설치에 표준·린트 파일이 포함되고 기존 파일 보존과 전체 회귀가 통과한다.

결과: [검증 보고서](../../03-analysis/features/company-development-standards.analysis.md). Python133개·Node137개 통과, 실제 ESLint 정상/위반12사례 포함. 소비 회사 앱의 lint 통합·실제 API/DB 구현은 별도다.
