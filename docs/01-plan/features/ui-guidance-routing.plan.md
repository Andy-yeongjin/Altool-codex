# UI 지침·자산 라우팅 확장 Plan

> 현재 문서 분류·검증 한계: [제품 문서 상태 색인](../../verification-status.md). 아래 과거 기록은 당시 실행 범위이며 최신 Altool 완료 판정을 대신하지 않는다.

상태: 구현 완료 — 자동 회귀·신규 macOS 설치 확인, 모델 완주 평가는 미수행

## 범위와 결정

사용자는 standard.yaml을 진입점으로 자산·배치/동작 지침·검증 기준을 찾고, 일반 개발과 Altool 명령 모두 탐색·적용·검증하도록 요청했다. 기존 표준 선택과 자산 사용 게이트를 확장한다. 헌법의 기존 필수 계약 원칙을 재사용하며 제품 헌법은 변경하지 않는다.

YAML에는 조건과 경로/ID만, 지침은 Markdown에 둔다. 작업별 지침은 standards에, 배포 자산과 결합된 회사 적용 지침은 공통 팩에 둔다. 기존 Altool 작성 체크리스트를 기본 회사 지침의 출발점으로 채택하되 KRDS 원문 전체를 필수 정책으로 승격하지 않는다. 회사 도입 전 조정은 지침·자산을 함께 새 릴리스로 배포한다.

## 성공 기준

- 로그인·검색·폼 등 의미 태그가 관련 지침·의존 표준·자산 후보를 반환한다. 관련 없는 원문 전체는 읽지 않는다.
- 모든 채택 자산의 resolve/read가 회사 지침·검증 항목과 참고 MD를 구분한다.
- 구현 전 표준/지침 탐색을 절차에 연결한다. 완료 게이트는 누락/중복/미검증/오래된 지침·소비 코드·관찰 파일 증거를 거부한다.
- 기존 ID·변형·UI 동작, 설치 표준 보존, 비 UI/legacy 경계를 유지한다. 새 팩 릴리스와 이전 증거 무효화를 명시한다.
- 자동 회귀와 임시 신규 설치에서 라우팅/차단 사례를 검증한다. 모델의 이해·전체 화면 의미 준수나 과거 미수행 브라우저 QA를 완료했다고 주장하지 않는다.

## 결과

과업별 지침/후보 라우팅, 165개 자산의 회사 지침/참고 연결, 사전 탐색 절차와 일반 개발·Step Check·oneshot 지침 증거 게이트를 구현했다. 자산 코드는 유지하고 회사 지침을 포함한 QA7 팩을 발행했다. 관련 절차·설치 안내·README·Spec을 동기화했다. Python121개/Node80개 및 무결성·설치 셸 구문·diff 검사 PASS. 세부 검증은 Spec과 회사 팩 검증 기록을 따른다.
