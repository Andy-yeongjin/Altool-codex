# 사내 공통 기반 PRD

상태: 초안 — 설치 프로젝트에서 범위를 확정한 뒤 사용

이 문서는 프로젝트 `prd/`에 선택적으로 복사한다. AI가 제품 목적과 원문을 검토해 internal-common 프로필 또는 필요한 계약을 선택하고 `standards/standard.yaml`을 관리한다. 사용자에게 YAML 편집을 요구하지 않는다. 루트 SPEC.md나 매 세션 전체 로딩을 요구하지 않으며 상세 설계는 기능별 Plan/Spec에 작성한다.

## 목적과 범위

수백 명 규모 사내 업무 시스템의 공통 기반을 만들고 업무 화면을 그 위에 추가한다. 한국어 전용, 자체 ID/PW 로그인(SSO 제외), 화면 등록·엑셀 일괄등록을 제공한다.

포함: 인증·사용자·조직·역할·메뉴·권한·공통코드·변경이력·접속이력·엑셀 업로드/이력·마이페이지.

후속 범위: 조직 시점조회 화면, 겸직·파견, 위임, 버튼 권한, 마스킹, 승인 프로세스, 다국어, 알림·메일, 인터페이스/배치 관리, 결재, 개인화, 다중 역할, MFA. 이들은 이번 구현에 자동 추가하지 않는다.

## 기능 계약

| 기능 | 요구 |
| --- | --- |
| 사용자 | 사번 로그인 ID, 성명·이메일·연락처·부서·역할·직위·상태, 관리자 초기화·잠금해제, 엑셀 등록 |
| 조직 | 상하위 트리·레벨·정렬·부서장·사용 여부, 순환 방지, 변경 스냅샷 |
| 역할 | 사용자당 1개 역할, ALL/DEPT/SELF 범위 |
| 메뉴 | 폴더/페이지 트리·URL·아이콘·정렬·사용 여부 |
| 권한 | 역할×메뉴 read/create/update/delete/export, 상하위 일괄 체크의 적용 범위 명시 |
| 공통코드 | 그룹/상세 2단 화면, 정렬·사용 여부, 엑셀 등록 |
| 감사 | 통합 검색·변경값 비교·레코드별 타임라인·배치별 조회 |
| 접속 | 로그인 성공/실패·시각·행위자·접속 정보 조회 |
| 엑셀 | 템플릿→검증/미리보기→확정→결과/이력, 오류내역 다운로드 |
| 마이페이지 | 본인 정보·비밀번호 변경 |

초기 역할: ADMIN(ALL), MANAGER(DEPT), USER(SELF). 실제 관리 메뉴 조회/변경 권한은 권한 매트릭스로 확정한다. USER의 관리 메뉴 접근은 거부하며 MANAGER의 허용 관리 조회 범위는 명시한다.

인증 정책 후보: 세션 8시간·자동 연장 없음, 실패 5회 잠금·관리자 해제, 최초/초기화 비밀번호 변경 강제, 주기적 변경 강제 없음. 원본의 bcrypt cost 10·9자/2종 정책은 도입 시 보안 요구와 라이브러리 기준을 검토해 인증 Spec에서 확정한다. 임시비밀번호 전달, 세션 폐기·회전·저장, CSRF, 잠금 카운터 동시 갱신도 함께 설계한다.

## 데이터 모델 설계 입력

| 엔티티 | 키/관계와 핵심 데이터 |
| --- | --- |
| sys_dept | dept_code, parent_dept_code, manager_emp_no, 이름·레벨·정렬·사용 여부 |
| sys_user | emp_no, dept_code, role_code, 이메일 유일성·password_hash·상태·잠금/비밀번호 변경 정보 |
| sys_role | role_code(ADMIN 등 업무 코드), 이름·data_scope·설명 |
| sys_menu | menu_code, parent_menu_code, 이름·종류·URL·아이콘·정렬 |
| map_role_menu | role_code + menu_code, CRUD·export 권한 |
| sys_code_group | group_code, 이름·설명·사용 여부 |
| sys_code | group_code + code, 이름·정렬·사용 여부, 추가 속성은 의미 있는 이름으로 정의 |
| log_audit | audit_id, 대상·키·작업·변경 필드·전후 값·행위자·시각·유입경로·batch_id |
| log_login | login_id, 사번·시각·성공/실패·접속 정보 |
| log_excel_upload | batch_id, 대상·파일명·건수·상태·행위자·시각 |
| his_dept | hist_id, 조직 전체 스냅샷·변경 구분·행위자·시각 |

타입·길이는 schema, 공통 컬럼은 data 표준에 맞춰 확정한다. 원본의 role_id 문자열과 _id 규칙, code 길이 20/30 혼용을 그대로 복사하지 않는다. 조직↔부서장 순환 FK와 초기 시드 순서를 설계한다. 조직 시점조회 화면은 후속이지만 스냅샷 저장은 이번 범위다.

## 화면과 API

목록은 검색·정렬·페이징·권한 있는 엑셀 내보내기, 상세는 변경이력 연결을 제공한다. 조직/메뉴는 트리+상세, 공통코드는 그룹+상세, 권한은 역할 선택+메뉴 매트릭스를 사용한다. 실제 디자인은 standards/design.md에서 확정한다.

공유 UI 후보: DataGrid, TreeView, ExcelUpload, UserPicker, DeptPicker, CodeSelect, AuditHistory, ConfirmDialog, Toast. 실제 사용 기능부터 공통화하며 예약 컴포넌트를 모두 선구현하지 않는다.

API 후보: /api/sys-user 및 /[empNo], /reset-password, /unlock, /api/excel/template/[entity], /validate, /commit. 사용자 입력의 메뉴 매핑이 아닌 서버의 작업별 권한 계약을 적용한다. 공통 경로·목록·응답·오류 코드는 standards/api.md를 재사용하고 기능 Spec에는 DTO와 권한/오류→문구 매핑 등 기능별 내용만 확정한다.

엑셀 기본 대상: 공통코드·조직·사용자·메뉴·역할별권한 UPSERT. 공통코드 그룹·역할의 선행 생성 경로도 제공한다. 템플릿은 데이터·코드값안내·작성요령 3개 시트, 후보 한계는 5,000행·10MB다. 확정한 한계에서 전건 원자성과 실행 시간을 테스트한다.

## 정책·시드 후보

공통관리 엑셀을 채택하면 작성요령 시트에 공통코드 → 조직 → 역할 → 사용자 → 메뉴 → 역할별권한 순서를 명시한다. 공통코드 그룹과 역할처럼 업로드 대상 밖의 선행 데이터는 별도 생성 경로를 안내한다. 조직·부서장 순환 참조 등 실제 의존성은 Spec에서 검증하며 이 순서를 모든 앱의 업로드에 강제하지 않는다.

초기 코드 후보: USER_STATUS(ACTIVE/INACTIVE/LOCKED), DATA_SCOPE(ALL/DEPT/SELF), MENU_TYPE(FOLDER/PAGE), ACTION_TYPE(INSERT/UPDATE/DELETE), SOURCE_TYPE(SCREEN/EXCEL/BATCH/API), YN(Y/N 표시). DB의 _yn은 BOOLEAN이며 표시용 Y/N 문자열로 저장 타입을 바꾸지 않는다. 실제 seed는 역할3개·최상위 부서·관리자·메뉴와 함께 기능 Spec에서 확정한다.

감사 보관기간 후보는 3년 후 아카이브이며 도입 회사의 정책에 맞춰 확정한다. 월별 파티셔닝은 양과 조회/보관 요구가 있을 때 설계한다. 인증 후보의 사번·이름 포함 금지 및 직전 비밀번호 재사용 금지도 인증 Spec에서 검토한다.

## 구현 의존 순서

1. 기술·명명·스키마·시드 계약 확정.
2. 감사 트랜잭션과 요청 행위자 경계의 통합 테스트.
3. 공통코드 한 엔티티로 업로드 엔진 검증.
4. 인증·권한 연결 후 실제 업로드 API 공개.
5. 코드→조직→역할→사용자→메뉴→권한 관리 기능 완성.
6. 감사·접속·업로드 이력과 마이페이지 검증.

각 기능은 Altool Plan→Spec→Run→Analyze→Fix→Browser→Report를 따른다. 위 순서는 기능 의존 관계이며 별도 수동 프롬프트 체인이 아니다.

## 인수 조건

- 일반 사용자 관리 API 직접 호출, 타 부서 단건 ID 접근, 초기 비밀번호 상태 우회를 거부한다.
- 감사 대상의 생성·변경·삭제·일괄 반영 모두 기록되고 실패 시 함께 롤백된다. 무변경 저장은 업무 diff를 만들지 않고 비밀값이 남지 않는다.
- 식별자 앞자리 0·날짜·오류 파일을 확인하고 오류 1건·서버 중간 실패 시 전체 미반영을 증명한다.
- 화면의 실제 클릭·입력·저장·권한 상태·모바일·접근성을 확인한다.
- Spec의 표준 적용표와 활성 원문을 독립 대조하고 실제 테스트/관찰 증거를 남긴다.
